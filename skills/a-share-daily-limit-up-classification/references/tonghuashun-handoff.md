# 分类到UI的交接

UI点击、入口、窗口、保存和恢复的唯一操作说明是 `$tonghuashun-ui-maintenance`。这里仅约定数据交接，不绑定模型、对话ID或执行钟点。

1. 交付已冻结的D日4.0分类JSON、绝对路径与哈希、实时分组目录、精确股票代码/名称、动作、全部`target_groups`及源组；写前校验通过。单分类一个目标，双分类两个目标，不能从旧单值字段截断。独立研究请求到报告结束，未要求UI时不扩展执行。
2. add不存在才加；已有只核验。move先把该码的全部目标组加入并保存逐组核验，再移出已确认错误主题组；任一目标未确认则保留源组。双分类另一有效目标和功能组不能删除。remove必须在本次授权范围，不能清空或删除整个分组。
3. 新建须完整查重、new_groups证据及授权成立；propose_group只报告、none不写。主窗口和其分组弹窗保持现有位置与大小。
4. 按 [数据契约](run-contract.md) 保存逐码逐目标组回执及保存后的核验。双分类少一组成功仍是pending/failed；单股可保留已成功目标，但不能报全成功。研究成功与UI成功分别记状态。局部故障按UI技能恢复，继续独立可执行项。
5. 调用方工作流可继续调用UI技能刷新连板和排序；本分类技能不自行读取交易或发送到固定档案对话，也不额外启动清理。
