# A股涨停原因分类

使用调用方指定的交易日D、运行目录和操作范围；不指定模型或对话。无执行时刻门槛，盘中可准备，最终名单未核实前不做收盘写入。独立研究请求只研究；明确要求完整分类维护或由每日总流程调用时，研究后接续UI。

1. 通过UI技能的 `scripts/local_groups.py snapshot` 读取同花顺当前本地分组文件，保存本轮目录、精确名称、成员、时间和顺序。使用其 `group_snapshot`（source=local_file）；正常不去UI盘点，不依赖共享历史分类档案或旧组名白名单。来源缺失按UI技能 `references/local-files.md` 处理，不以旧档案补成当前事实。换对话续作使用调用方传入的原运行目录。
2. 取得D日完整非ST最终涨停集合，核对来源差异及最终性；ST/*ST/风险警示在名单层排除。数据失败不能当空集，无法解释的名单差异先待核验。
3. 读取 [分类契约](references/classification-contract.md) 和 [分类偏好](references/classification-preferences.md)。每股至少三家不同原因网站交叉核验，优先选股宝、东方财富、同花顺，允许可靠补充。保留原始原因、所属日期、原页及转载关系；搜索摘要和公司长期标签不能充当当日原因核验。
4. 面向短线题材归因：按当日实际交易逻辑、调用方确认的分类粒度及实时组名选主分类，优先复用含义准确的现有组。对每个候选主分类评高/中/低置信度并写依据；中高置信度且来源与排除条件合格时直接归类。低置信度必须按分类契约继续发散搜索，并分析当日个股与候选板块的走势联动，不能只收集三张原因卡就写“未解决”。
5. 一个原因明显主要时单分类；两个不同原因均有中高置信度、难分主次时双分类，两个目标都实际写入和核验。小众排除按分类偏好的“三项任意两项”规则逐项核实，不使用板块名称黑名单；资料缺失不算0。独立事件、规则排除和补查后仍无法判断的个股，完整保留并在报告末尾解释。
6. 按 [数据契约](references/run-contract.md) 保存分类JSON；生成UI清单时由 `scripts/build_ui_manifest.py` 内部做一次pre-ui校验，通过后才能产生动作，不重复手工跑相同检查。独立研究需要校验时可用 `scripts/validate_classification.py --input ABS_PATH --stage pre-ui`。校验器验证材料和字段条件，不替代对原页真实性及市场归因的判断。脚本路径从实际技能目录解析。
7. 有UI任务时读取 [交接与回执](references/tonghuashun-handoff.md)，再调用 `$tonghuashun-ui-maintenance`。按其操作函数文档加载一次 `scripts/ui_ops.mjs`，复用控制器完成高频动作；不从历史聊天拼写临时函数。点击、窗口定位、局部恢复只由UI技能规定。每批按 `saveBatch → local_groups.py verify → confirmSaved` 确认目标代码、实际改动组数量与差集，成功即停止检查。仅本地文件缺口触发局部UI回读，不扫描未改组。报告实际结果；研究完成不能代替UI完成。

每只股票保留代码前导零，覆盖完整最终名单；归类目标为一个主组或两个并列主组，备选标签不自动写入，功能组不按题材去重。新增组须完整查重、列出成员、联动规模和不复用理由；普通归入已有大类不套用“必须形成强主线”的门槛。补查后仍缺关键证据的股票留在完整名单及报告末尾，不拖住可独立处理的股票。

工具、网络或UI失败时保留原始材料和断点，不能以空数据覆盖历史证据。最终回复逐只“代码 名称 → 实际组/未分类原因”，附原页/本地证据路径和UI缺口；不生成HTML，不启动完整深度复盘、评级、交易读取或下单。
