# 分组与成员排序

只在调用方明确要求排序时运行。调用方提供完整目标顺序，或已核验的指定日期非ST最终涨停集合；本技能不研究行情原因。历史报告重渲染不自动覆盖当前客户端。

## 指定顺序

系统“自选股”固定第一，不移动。完整目标必须包含当前所有精确分组，唯一且无遗漏。由 `scripts/ui_ops.mjs` 的 `reorderGroups(fullOrder)` 将系统组之外的目标整体逆序逐项置顶，每次使用当前控件。已满足目标时不操作。

分组用左侧容器和箭头；组内股票用右侧容器。置顶/置底不是逐行上移/下移，不使用未验证拖拽。不改变组内成员。

## 按当日非ST最终涨停数量排序

固定前缀由调用方提供，未提供时只固定系统“自选股”。例如某个工作流可以配置“自选股→观察→连板→核心”，不要求所有用户建立同名组。缺少请求中的固定组时报告，不擅自创建、恢复已删除组或用近似名称替代；核心成员不自动增删。

1. 从本轮 `local_groups.py` 快照取得当前组名、顺序和成员，不重开UI逐组盘点，也不依赖历史白名单。普通排名组须有完整成员；系统自选股成员未知时保持null，不影响其固定前缀身份。
2. 复用上游已核验的同日非ST收盘最终涨停全集。盘中触板和炸板不计入；日期、最终性、风险警示过滤或覆盖不全时不填0。
3. 每组数量为该组唯一代码与最终集合的交集大小，同股在不同组各计一次。固定前缀外按数量降序，同数保持本地原相对顺序，0只排后。不是平均涨幅、占比或主观强度。
4. 目标为固定前缀加普通组排名。验证其与当前全部分组集合完全一致、无遗漏或重复，然后复用本轮控制器执行整体逆序置顶，不为每组重新打开或保存设置。
5. 最后一次 `saveBatch → local_groups.py verify → confirmSaved` 核对本地完整组序与目标逐项相等，成功即结束，不重复扫描未改组成员。本地仍无法确认才从左表读取全序一次，不读右表成员；主页拼接标签不作最终顺序证明。

可选离线工具 `scripts/plan_group_order.py` 接受 `examples/sorting-input.json` 的规范化输入，计算数量、目标及置顶序列。调用方可将本地快照按order转换为组数组，并把每个members对象提取为代码字符串；系统成员未知保持null和complete=false，不能伪造空集。脚本只计算计划，不读取行情或控制桌面，也不证明保存成功。

报告给出分组、当日涨停数、原/最终位置与保存确认，缺口单列，不把排序当作涨停原因或交易评级。
